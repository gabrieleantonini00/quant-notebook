Large Language Models

Tokenization and Generation

A tokenizer turns text into token IDs. A token may be a word, part of a word, punctuation, or another fragment; it is not always a whole word. The model converts those IDs into vectors and uses Transformer attention to build context-sensitive representations. It then produces a score, or logit, for every possible next token.

A causal language model generates autoregressively, sampling each token from its conditional distribution given the preceding tokens:

$$p_\theta(x_t\mid x_{1:t-1})\qquad\text{next-token distribution given earlier tokens}$$

Sampling turns logits $z_v$ into probabilities. With a positive temperature $T$, the probability of token $w$ is:

$$p_T(w\mid x_{1:t-1})=\frac{\exp(z_w/T)}{\sum_{v\in V}\exp(z_v/T)},\qquad T\gt 0.$$
ControlWhat it changes
TemperatureLower positive values concentrate probability on the highest-scoring tokens; higher values spread it out. A setting of zero is a special decoding rule, not division by zero.
Top-pSamples only from the smallest set of tokens whose cumulative probability reaches a chosen threshold $p$.
Output limitCaps the number of tokens generated. It controls length and cost, not factual accuracy.

Pretraining and Post-Training

These are distinct kinds of training, not a fixed recipe used identically for every model.

Pretraining

Text and code are collected, cleaned, filtered, and tokenized. The model learns to predict tokens across many contexts by reducing next-token loss. Data quality, mixture, compute, architecture, and training objective matter alongside parameter count.

$$\mathcal{L}_{\mathrm{pre}}(\theta)=-\sum_{t=1}^{N}\log p_\theta(x_t\mid x_{1:t-1}).$$

Pretraining yields a base model; instruction following and preference alignment are addressed in post-training.

Instruction Tuning

Supervised fine-tuning (SFT) trains on examples of prompts and desired responses. It can teach the model to follow instructions, use conversational roles, and produce a requested format. The weights change during this step.

Preference and Outcome Feedback

Further post-training may favor responses that humans prefer or answers that pass a verifiable check. In reinforcement learning from human feedback (RLHF), people compare candidate responses, a reward model learns from those comparisons, and the assistant is optimized against that signal. Other approaches use AI feedback or directly verifiable rewards. A high reward is still not a guarantee of truth or safety.

Task Adaptation

The first decision is whether the task needs new model weights, or whether the existing model can work with better context and tools.

ApproachWhat changesUseful when
Prompting and examplesOnly the input context; model weights stay fixed.You need instructions, a format, or a few demonstrations.
Retrieval-augmented generation (RAG)Relevant documents are retrieved and inserted into the context at question time.Answers should use a changing collection of notes or records.
Fine-tuningModel weights are updated using task examples.You need a learned behavior that prompting alone does not provide reliably.
Feature extractionA frozen model supplies embeddings to a separate classifier or regressor.You need predictions from text with a smaller downstream model.

RAG supplies external context at inference time. Fine-tuning changes learned behavior; maintaining current factual knowledge still requires an explicit data-update or retrieval process.

Low-Rank Adaptation (LoRA)

Full fine-tuning updates many parameters. Low-rank adaptation (LoRA) instead freezes an existing weight matrix $W_0$ and learns two smaller matrices. For $W_0\in\mathbb{R}^{d\times k}$ and rank $r$:

$$W=W_0+\frac{\alpha}{r}BA,\qquad A\in\mathbb{R}^{r\times k},\quad B\in\mathbb{R}^{d\times r}.$$

The adapted matrix adds $r(d+k)$ trainable entries rather than updating all $dk$ entries of $W_0$. Savings depend on the chosen rank and which matrices are adapted.

Agents and Harnesses

A language model produces responses and may request a tool call. An agent harness is the surrounding software that turns this into a controlled, multi-step workflow. It supplies instructions and context, presents available tools, executes permitted calls, returns their results to the model, manages session state, and decides when to stop or ask for help. The harness is not another set of learned model weights.

PartRole
ModelInterprets the current context, generates text, and can choose a tool to request.
ToolsPerform concrete actions such as searching notes, running code, or reading a file.
SkillsReusable instructions or resources for a particular workflow; they guide behavior but do not execute actions by themselves.
HarnessRuns the model–tool loop, passes observations back, tracks context and permissions, and records or checks the outcome.

Execution Cycle

  1. Context: assemble the request, instructions, state, and available tools.
  2. Inference: generate a response or a structured tool request.
  3. Execution: validate and run the permitted call, then append its result to the context.
  4. Termination: continue the loop or return the final response, subject to stopping criteria and resource limits.

This distinction matters: a stronger model can still fail with missing context or unreliable tools, while a good harness cannot make an unsupported claim true. Evaluate both the model's answers and the surrounding workflow.

Evaluation

Fluent text is not evidence. For factual tasks, inspect whether the answer follows the supplied source; for exact calculations, use a calculator or code and check the result. For tool-using tasks, inspect whether the tool result supports the claimed action. Test representative and difficult cases, including missing information, ambiguous instructions, and incorrect retrieval. Longer reasoning traces or more tool calls can help in some cases but do not guarantee a correct result.
